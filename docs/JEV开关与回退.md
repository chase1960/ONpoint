# JEV 开关与规则回退：实际实现

日期：2026-10-24。本说明针对当前代码。大模型生成方案仍未接入；本次加入的是可选判定模型的运行模式与降级，不是取消规则或扩大业务权限。

## 三档开关

| 界面 | 模式值 | 实际行为 |
| --- | --- | --- |
| 关闭 · 只用规则 | off | 不调用 JEV，原规则判断 |
| 影子对照 | shadow | 对允许样例调用模型并记录结果，规则仍决定路径 |
| JEV 辅助分流 | assist | 在覆盖范围和概率门内采用模型判断，其余保留或回退规则 |

开关位于网站顶部，覆盖三个页签。POST /api/state 的 judge_mode 动作仅接收 off、shadow、assist。开关是本机演示的运行时设置，重启按 JEV_MODE 环境变量恢复，不将外发权限默认持久化。

前端不能提交密钥、修改接口地址、授予外发许可或绕过服务端配置。缺密钥/外发许可时，影子和辅助选项不可启用；直接伪造请求也会被后台拒绝。现有应用仍未加入生产身份与角色鉴权，不能将此管理开关原样公开。

## 哪些输入会调用模型

先检查以下条件：

1. 模式不是 off。
2. 服务端密钥、接口和合成数据外发许可均有效。
3. 没有处于限流/失败冷却期。
4. 案件未结案、未由人工持有、没有已有风险/任务。
5. 不是已明确识别的风险、人工、政策或未开放业务规则。
6. 文本与获准的合成样例原文完全一致。

符合时才调用；否则走规则并记录原因。自由输入、真实业务资料不因打开开关而自动获准外发。

当前使用两个独立的 Choice 判定点：是否询问既有退款的进度、是否明确要求人工。问题一次合并发送，state 只有本次合成消息，不外发订单详情、支付信息或完整案件历史。它不是完整四类业务模型：静态政策、具体任务权限和风险控制仍由代码处理。

## 辅助模式决策表

所有模型输出首先经过结构、答案集合、概率分布与返回大小校验。

| 情况 | 实际采用 |
| --- | --- |
| 命中硬规则、人工接管或已有风险 | 规则；不让模型取消风险 |
| 明确人工意愿 yes 概率至少0.90，领先其他选项至少0.20 | 同案交人工；不执行任务 |
| 人工意愿 no 至少0.90，退款进度 yes 至少0.85，均有0.20领先差 | 可补充识别退款进度；仍先只读查询 |
| 不确定、矛盾、范围外、低概率、模型否定已有退款进度规则 | 原规则，记录回退原因 |
| 超时、断网、认证/额度/限流/服务错误、非法响应 | 原规则，记录实际错误；失败不伪装成“否” |
| 等待期间开关/案件改变 | 丢弃旧模型意见，按最新状态和规则处理 |

上述数值只是保守的初始工程参数，不是已校准的业务阈值，更不是“达到阈值即保证正确”。采用的是选项概率和领先差，不是直接把 confidence 当成正确概率。没有在线测试或独立样本验证，不宣称效果提升。

模型不修改 TrackingRequested、不生成客户授权、不直接创建 Task。即使识别为退款进度，也必须查询有效订单；用户明确申请追踪、流程匹配、政策核验、方案卡确认、执行前重查与幂等检查全部保留。

如果回退后规则也无法理解，请求仍会澄清或转人工，不编造答案。

## 故障和并发处理

- 单次调用默认2.5秒，不自动重试；已有服务端网络配置可显式调整超时（500–30000毫秒），到期仍回退规则，不由前端任意延长等待。
- HTTP 401/402/403/429，或连续3次其他模型失败，进入30秒冷却；期间新请求直接用规则，不反复等待或请求模型。
- 冷却结束后仅在下一次符合条件的用户请求到达时尝试，不运行后台自动探测。
- 外部模型请求不持有全局案件锁；等待期间仍可读取状态、转人工或关闭开关。
- 返回时核对客户端配置身份与案件内容指纹，禁止旧判断覆盖新案件状态。
- 在线批量对照也在锁外执行，首个错误即停止；关闭或改变模式后不再发送后续样例。已经发出的请求无法“撤回外发”，返回结果可被丢弃。
- 模式修改如遇数据库事务失败，运行客户端和界面状态一同恢复；模型接口的限流冷却是独立运行保护，不声称可回滚外部计费。

## 可见证据

- 每案显示最近一条消息由规则还是 JEV 判断，是否回退，以及原因。
- 原始 JEV 答案保存在 Judgments，不用人工标签替换模型结果。
- 记录 HTTP 状态、耗时、tokens、问题版本及实际请求体；请求体不含密钥或请求头，密钥字符串也从模型 state 中剔除。
- 发布流程回放依然隔离运行规则与业务引擎，不将其声称为完整 JEV 路由评测；模型模式与降级另有回归测试。
- 历史案件没有 Intake 记录时如实显示“尚无记录”，不会推算它当时使用了哪种模型。

## 配置与边界

默认建议 off。准备在线验证时，先配置 TYPESAFE_API_KEY，明确仅合成样例外发，再设置 TYPESAFE_ALLOW_SYNTHETIC_EGRESS=true；JEV_MODE 可设 shadow 或 assist。已有进程不会自动获取新环境变量，需要由带有配置的新进程启动。

本轮没有调用真实 TypeSafe 推理接口，没有使用商业密钥发起推理，没有在线费用或质量收益结果。在线试验仍需要用户明确授权数据范围及调用预算；已注册账号不等于密钥和试验授权都已就绪。最后验收时，本机服务配置已就绪；只切换三档模式并恢复原 shadow，模型观察数仍为0。

当前程序重启后继续读取 data/ota-routing.db，保留已有案件、方案和任务；没有修改合成数据集或迁移/删除旧库。

## 实现入口

- judge_router.go：决策表、模式切换、锁外请求、过期结果检查、规则回退。
- jev.go：服务端配置、HTTP 调用、类型校验、超时、冷却、请求审计。
- main.go：锁外执行模型调用、事务与客户端状态一致性。
- engine.go：采纳受控语义判断，政策/确认/工具链不变。
- dist/presentation.js、dist/app.js：顶部开关、每案判断来源、回退原因、实际请求查看。
- judge_router_test.go、presentation.test.cjs：故障、权限、并发与展示回归。

官方资料已核对：[OpenAPI](https://api.typesafe.ai/openapi.json)、[置信度与概率](https://docs.typesafe.ai/confidence)、[意图路由](https://docs.typesafe.ai/patterns/intent-routing)。本次保留现有两项 Choice 协议，不凭空切换 SDK 或变更模型版本。
