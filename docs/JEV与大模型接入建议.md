日期：2026-10-24。区分本轮已完成与后续待密钥、外发许可和实测的能力。

**本机接入更新（2026-10-24）**：已按“CAREFLPW打开方式”对话的方案，将 Windows 已启用的系统代理和用户环境密钥读取接入 `Start-ONpoint.ps1`，并给 Go 客户端增加独立代理配置。已用该 Go 客户端实际读取官方模型列表成功；未执行在线推理。`jev.settings.json` 已配置 shadow 模式、仅合成样例外发和 15 秒超时，界面触发合成样例判定时才产生推理用量。下面早期关于“未配置密钥”的描述为历史阶段记录；当前配置及操作以 README 的 JEV 段落为准。

## 先由你准备

1. 在本机配置 TYPESAFE_API_KEY，不在聊天、浏览器前端或 Git 仓库中粘贴长期密钥。现有进程不会自动获得之后新增的环境变量，配置后需在带有该变量的新进程中重启服务。
2. 是否允许仅把 fixtures/ota.json 中的合成测试原文发给 TypeSafe，需要明确决定。未获许可，保持关闭。不要输入真实订单、姓名、证件或支付信息。
3. 大模型平台选一个即可：百炼 qwen-flash，或者已有的 DeepSeek 官方 API。创建独立演示 Key，限制可访问模型，设置预算告警；充值与付费由你自行决定。
4. 大模型正式调用前同样需要明确允许合成事实与提问发送到所选平台；本轮没有接入或调用生成式模型。

现有 JEV 的三个启用条件是：TYPESAFE_API_KEY、JEV_MODE=shadow、TYPESAFE_ALLOW_SYNTHETIC_EGRESS=true。不要为了启动网站就盲目打开外发开关。

## 一、现在要不要公开网站

建议：现在做好部署准备，稳定主交互后公开受保护演示，不必等全部视觉细节定稿。

- 现在：保留本机验证，固定接口契约、案件/方案模型、启动与备份方式；设计评委独立沙箱和权限。
- 前端主流程稳定：接入 HTTPS、受控入口、服务端角色权限、每位体验者的数据隔离、限流与模型配额后再开放。
- 后续视觉改动：正常迭代，不必重新设计后台。但不能将现有全量状态接口原样公开。

本轮没有开放公网、修改监听限制或把“前端页面”误称为已完成部署。

## 二、本轮已经修改的实际主链

用户输入 → Go 规则与状态判断 → 四类服务分流 → 事实/政策/流程核验 → 只读答复，或者生成方案卡 → 明确确认后才创建沙箱追踪任务 → 同案人工与受控流程复用。

| 类别 | 当前实现 | 结束条件 |
| --- | --- | --- |
| 静态咨询 | 读取固定演示政策并显示版本，不是 RAG | 用户确认咨询足够，无任务 |
| 动态咨询 | 查合成订单和支付轨迹，如实说明状态 | 可直接结束，不强制追踪 |
| 办理请求 | 明确申请追踪 → 核验政策与已发布流程 → 方案卡 | 客户再次确认才执行，有 TR 回执 |
| 不明确/高风险/人工 | 缺信息先澄清；争议/越权/未开放接口等交人工 | 保留上下文，不自动抢回处理权 |

Route 记录本案当前采用的服务处理路径；办理请求若因流程缺口交给人工，Route 显示人工路径，Intent 和 TrackingRequested 保留原业务诉求。

同一请求可以先咨询，再主动升级为办理。用户“申请追踪”只是要求生成方案，不等于授权工具执行。

### 本轮修复

- 动态咨询与办理分开，查询不会自动生成任务或强制人工。
- 新增 request_tracking、consultation_done、refresh_plan 三个受控动作。
- 人工偏好不再写成业务风险；投诉、赔偿、越权仍然保持阻断。
- 人工接管后可以接收补充订单/退款意图，不会被自动 Agent 抢回。
- 原方案过期可重新查询、生成新 PLAN、新令牌；旧方案作废，仍需重新确认。查询失败/风险未解除时不得恢复执行。
- 人工或自动方案遇用户取消、切换业务时，旧方案不能继续执行。
- 方案卡内容结构保留，前端增加四类分流标签、只读咨询出口、重新核验入口和确认弹窗内恢复按钮。
- JEV 人工意愿评分与业务意图拆开，避免把“要人工查退款”错误标成“不要求人工”。

新数据集为 ota-synthetic-v2-routing，6 个订单、22 条合成问法。旧库及旧数据源保留，不删除。

## 三、加入 JEV 后应怎样工作

### A. 当前可启用：影子对照

合成样本 → 同时获得关键词规则判断和 JEV 观察 → 实际业务继续由规则与政策门决定 → 记录判定、置信信息、耗时、tokens 和失败 → 独立复核差异。

当前只有“是否退款进度”“是否明确要求人工”两个 JEV 判定点；尚不是完整四路语义路由。

当前未配置密钥、未获新增外发许可，也没有在线质量、成本或效率结论。影子模式会增加调用开销，不能把它本身描述为降本。

### B. 之后可实现：辅助语义路由

身份与硬风险规则
→ 明确按钮直接走代码；歧义自然语言送 JEV
→ 意图候选 + 是否需要澄清 + 人工意愿 + 不确定信号
→ 静态咨询 / 动态咨询 / 办理 / 澄清或人工
→ 按需调用大模型，不把大模型作为所有请求的必经环节
→ 政策校验与方案卡
→ 客户明确确认
→ 白名单工具
→ 可验证回执。

JEV 只提出意图，不知道未经查询的订单真实状态，更不能授予退款权限。TypeSafe 官方的路由模式允许分流到确定性逻辑、大模型或人工；置信信息应允许弃权，阈值需按业务风险验证，不照抄示例数值。

参考：[TypeSafe 意图路由](https://docs.typesafe.ai/patterns/intent-routing)、[置信度含义](https://docs.typesafe.ai/confidence)。

### 预期收益与必须实测的代价

| 预期作用，尚未证明 | 如何验证 |
| --- | --- |
| 改写、否定、口语表达比关键词覆盖更好 | 独立标注的表达变体，比较各路混淆矩阵 |
| 减少不必要的大模型调用 | 与“大模型处理全部请求”的同输入基线比较实际调用数和总 tokens |
| 风险/不确定请求更可控 | 检查错分自动办理、错误放行、弃权与人工接管 |
| 路由逻辑更易维护 | 看新增表达是否减少规则修改，同时保证政策门不变 |

同时报告：超时/错误/未评分占比、P50/P95 总耗时、用户轮数、工具结果符合预期情况。不把 confidence 当成“业务一定正确的概率”。

现阶段 JEV 调用仍在全局锁内同步执行，可能增加等待。要接管在线路由，先把外部推理从全局状态锁移出，并以案件版本检查回填结果，避免将过期判断写回新状态；不建议仓促取消锁。

当前关键词和模板没有模型调用费，增加 JEV + LLM 不会自动比现在便宜。只有对明确的替代基线实测后才能谈成本改善。

## 四、一个 Go 服务还是四个独立 Agent

这不是“普通 Go 与高级 Agent”的二选一：Go 是实现与部署方式，Agent 是决策/执行模式，二者可以共存。

建议本期：**一个部署单元，一个编排器，职责清晰的逻辑模块。**

| 方式 | 对本期的影响 |
| --- | --- |
| 同进程模块化 | 案件状态、授权和事务一致；便于定位问题和单人部署 |
| 同进程多个专业处理器 | 可以分别优化提示词、模型、用例和工具，无需增加网络服务 |
| 多 Agent 串行交接 | 可能重复传递上下文、增加模型轮次；不天然更快 |
| 多 Agent 并行处理 | 仅适合互不依赖的读操作/分析；依赖前序证据的办理仍须有序 |
| 独立进程/服务 | 不同团队、负载、安全边界、故障隔离需求明显后才更值得 |

下一步可以明确模块边界：分流器、证据查询器、方案生成器、执行器、人工交接、流程资产管理。业务授权仍统一检查，不能每个 Agent 自己决定是否可执行。

可优化空间来自契约清楚、可观测、各模块有独立评测，而不是来自“Agent 数量多”。

## 五、大模型接什么

### 推荐：百炼 qwen-flash；已有 DeepSeek 则先复用

本次需要的不是超长推理，而是：

- 基于已经查得的事实组织客户能理解的解释；
- 对缺失信息提出受限澄清问题；
- 在已审核流程和白名单动作内草拟结构化方案，输出可被服务端校验的数据；
- 不制造事实、不承诺到账、不替代政策和客户确认。

| 平台/模型 | 官方查询到的价格示例 | 建议 |
| --- | --- | --- |
| 阿里云百炼 qwen-flash | 华北2北京，输入不超过128K：输入 ¥0.15、输出 ¥1.5 / 百万 tokens | 当前低成本演示候选；使用短上下文 |
| DeepSeek 官方 deepseek-flash | 未缓存输入 $0.15–0.30、输出 $0.60–1.20 / 百万 tokens，按时段 | 已有账号/密钥就先复用，采用非思考模式做对照 |

价格核验日期为 2026-10-24，不同地域、模式、上下文和模型版本会改变价格，最终以实际账单为准。二者不是同一币种，不据此声称谁“全网最低”或更适合所有中文业务。

来源：[百炼价格](https://help.aliyun.com/zh/model-studio/model-pricing)、[DeepSeek 官方价格](https://api-docs.deepseek.com/quick_start/pricing/)、[百炼 Key 与地域配置](https://help.aliyun.com/zh/model-studio/get-api-key)。

注意：平台注册的账号、网页聊天会员、Coding/Token Plan 与可供本项目后端使用的按量 API Key 不是同一件事。Key、地域、Base URL 和所选模型需要匹配；首轮用按量接口做有限样本验证，不先购买长期套餐。

### 接口设计，而非本轮已完成

ModelAdapter 输入：当前问题、脱敏工具事实、证据引用、政策条款、可用流程和允许动作。

ModelAdapter 输出：问题理解、缺失信息、引用事实、建议方案、流程 ID、白名单步骤、限制说明。

服务端校验流程 ID、证据引用、步骤、权限和当前版本。失败则退回确定性模板或人工；模型不直接拿数据库写权限和资金工具凭证。

下一步先固定一个平台接入，同一组用例比较“纯规则/模板”“规则 + LLM”“JEV 辅助 + 按需 LLM”，再决定是否需要昂贵模型或独立 Agent。
